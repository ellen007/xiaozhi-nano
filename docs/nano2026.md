# Nano 2026 port

This branch starts from upstream `78/xiaozhi-esp32` commit
`184a688cd04564c15f035cee09c0f61889fc8e9d` and adds two independent board targets.
It does not migrate all custom application features from the older Nano fork.

| Board directory | Firmware variant |
| --- | --- |
| `esp32s3-nano` | `esp32s3-nano-2026-n16r8` |
| `esp32s3-nano-pro` | `esp32s3-nano-pro-2026-n16r8` |

## Build

Activate ESP-IDF >= 6.0.1 (prefer 6.1), then select the board matching the PCB:

```sh
python3 scripts/build.py esp32s3-nano-pro --name esp32s3-nano-pro-2026-n16r8 --language zh-CN
# Or, for the original Nano wiring:
python3 scripts/build.py esp32s3-nano --name esp32s3-nano-2026-n16r8 --language zh-CN
```

Flash size, Octal PSRAM and partition defaults are inherited from the pinned
upstream. Language and wake-word choices remain build options.

## Compatibility and unresolved hardware

- Nano uses ESP32 I2S RX=11, TX=13; Pro uses RX=13, TX=11. Do not interchange them.
- GPIO36 backlight conflicts with N16R8 Octal PSRAM. PWM is disabled by default;
  enabling it on this pin is rejected by a compile-time assertion. A dark display
  is possible until the actual backlight wiring is resolved.
- Pro SD_D2=GPIO37 also conflicts with Octal PSRAM; SD mounting is not implemented.
  Disabling a driver does not remove physical loading on a memory bus.
- Pro drives six WS2812 LEDs on GPIO45; GPIO21 is not used as WS2812 output.
  Nano RGB and reserved GPIO1 touch input are disabled pending hardware verification.
- ADC battery percentage and device-side AEC are not enabled.
- Any physical pin changes require a distinct hardware identity or firmware variant
  and corresponding OTA routing. Do not overwrite another board's released pin map.

See each board's `README.md` and `config.h` for controls and feature switches.

## Validation status

Host tests, board discovery, patch application and formatting checks are available.
A successful host test run is not an ESP-IDF firmware build or hardware validation.
No flashable binary is included. Full target compilation and physical tests are
still required, including audio, display, LED chain, buttons, provisioning and OTA.

The repository's original `main` branch is retained. Future upstream updates should
be fetched, merged into the adaptation branch, and revalidated before release.
